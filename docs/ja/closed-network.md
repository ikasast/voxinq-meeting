# 閉じたサーバーで動かす

Voxinq は、準備を済ませた後は**インターネットへ一切出られない**機械で動かせます。Voxinq 専用の
サーバーを用意し、入ってよい端末からだけ届き、そこからはどこにも何も送れない — という構成です。
組織で導入する人や、サービスとして誰かに提供する人向けのページです。
[← 日本語ガイドに戻る](../../README.ja.md)

> **検証状況**: アプリ側は 4.0.0 の CPU 版イメージで確認済みです。Voxinq のコンテナを Docker の
> `internal` ネットワークに置き、名前でもアドレスでも外に届かない状態で、アップロードから文字起こし・
> 話者分離・議事録までを通しました。モデルを揃えた後は、閉じた状態でもオンラインと同じく 1 分足らずで
> 終わり、`HF_HUB_OFFLINE` の有無でも変わりませんでした。下の [CPU 版イメージの注意](#準備のしかた)は
> この検証で見つかったものです。機械全体のファイアウォールと Tailscale の許可リストは、このプロジェクト
> では通しで試していません。

## 閉じると何が防げて、何が防げないか

**出口を閉じる**と、サーバー上で何が動いていても — 侵害された依存パッケージ、設定ミス、誰も確認して
いない更新 — 持っているデータをどこにも送れなくなります。**入口を閉じる**（インターネットに何も公開せず、
自分たちのネットワークだけにする）と、外の誰もアプリにそもそも届きません。Funnel を使わない Tailscale
構成は後者を既に満たしており、閉じたサーバーは前者を加えるものです。

**防げないのは、既に内側にいる相手**です — 入ることを許された端末や、アカウント。こちらは
[入ってよいものを固める](#入ってよいものを固める)で扱います。

## Voxinq 自身が外に送るもの

既定の構成では、**動いている間 — 録音・文字起こし・話者分離・議事録作成 — は何も送りません**。

- 文字起こしと議事録はその機械の上で動きます。外に出すのは**外部 AI** 拡張機能で、既定はオフ、
  使うときは送信先を画面に表示します
- Web アプリは実行時にテレメトリを送りません（Next.js の匿名テレメトリはビルド時のもので、公開
  イメージではビルド済みです）
- Funnel（tailnet の外への閲覧専用の共有）は拡張機能で、既定はオフです

インターネットが要るのは次の場面だけです。

| 何を | いつ | 閉じたサーバーでは |
| --- | --- | --- |
| Docker イメージ（`ghcr.io`） | 導入時と更新のたび | `VOXINQ_VERSION` を固定し、別の機械で取得して持ち込む（[後述](#閉じたサーバーの更新)） |
| 文字起こし・話者分離・翻訳のモデル（Hugging Face） | それぞれ初めて使うとき | 準備中に一度ずつ使う。`hfcache` ボリュームに残る |
| 議事録のモデル（Ollama） | pull したとき | 準備中に pull する。`ollama` ボリュームに残る |
| モデルの検索（*設定 → LLM*） | 管理者が「検索」を押したとき | 使えない。画面にその旨が出て、インストール済みのモデルは選べる |
| Android アプリの更新 | アプリの更新時 | 取りに行くのは**スマホ**で、サーバーではない。手で APK を入れてもよい |

モデルが揃ったら、`stt` サービスに **`HF_HUB_OFFLINE=1`** を設定してください。これが無いと、
モデルのライブラリが手元のファイルを使う前に新しい版を確認しようとします。ネットワークが即座に
拒否する環境なら損はなく（検証でも差はありませんでした）、パケットを黙って捨てるファイアウォール
では、その確認のたびにタイムアウトまで待つことになります。

## 構成を選ぶ

1. **Tailscale を使い、出口を Tailscale だけに絞る（推奨）**: サーバーのファイアウォールで、
   Tailscale が必要とする通信（[一覧](#tailscale-が必要とする通信)）だけを外に通し、他は全て止めます。
   スマホを含め、開いた機械と同じように動きます
2. **Tailscale の調整役を自前で動かす（Headscale）**: 建物の外には何も出ません。代わりに HTTPS の
   証明書を自前の認証局（CA）から出す必要があり、全端末にその CA を信頼させる必要があります
   （→ [Android アプリ](#android-アプリ)）
3. **Tailscale を使わず、社内ネットワークだけ**: ネットワークは最も単純ですが、証明書の問題は 2 と同じで、
   建物の中からしか使えません

**HTTPS は省けません。** ブラウザがマイクを使わせるのは HTTPS（または `localhost`）のページだけで、
Android アプリのリリース版も HTTPS でしか通信しません。

## 準備のしかた

順番が大事です。**オンラインで**準備し、全てのモデルを一度ずつ使ってから閉じます。

1. 通常どおり導入します（[詳しい導入手順](setup.md)）。`.env` の `VOXINQ_VERSION` は `v4.0.0` の
   ように固定してください
2. 議事録のモデルを pull し（`docker compose exec ollama ollama pull qwen3:8b`）、使う拡張機能を
   オンにします（*管理 → 拡張機能*）
3. **使う機能を全部通して、会議を 1 件処理します** — 文字起こし、話者分離、オンにしたなら翻訳や感情も。
   それぞれ初回にモデルをダウンロードします
4. `docker-compose.yml` の `stt` サービスの `environment:` に `HF_HUB_OFFLINE: "1"` を足し、
   `docker compose up -d`
5. **閉じます**: 構成 1 ならファイアウォールの規則を適用、2 と 3 なら機械をインターネットから外します
6. もう一度会議を処理して、閉じた状態で動くことを確かめます

> **4.0.0 以前の CPU 版イメージ**は、whisper.cpp のモデルを `hfcache` ボリュームの外に置くため、
> コンテナを作り直すと（更新時や手順 4 自体でも）消えてしまい、閉じたサーバーでは文字起こしが
> できなくなります。これらのバージョンでは、手順 3 の前に `stt` サービスへ
> `XDG_DATA_HOME: /data/huggingface/xdg` も足してください。以降のイメージは自動でボリュームに置きます。

## Tailscale が必要とする通信

構成 1 では、サーバーのファイアウォールで次を外に通します。

- **Tailscale の調整サーバー** — `controlplane.tailscale.com` と `login.tailscale.com`、TCP 443。
  鍵と「誰が誰に届いてよいか」はここから来ます。会議の中身は通りません
- **Tailscale の中継（DERP）** — `derp*.tailscale.com`、TCP 443 と UDP 3478。端末同士が直接
  つながれないときだけ使います。同じネットワーク内なら普通は直接つながります
- **直接接続** — 端末そのものへの UDP 41641
- **Let's Encrypt** — `acme-v02.api.letsencrypt.org`、TCP 443。`tailscale serve` の証明書は約 90 日で
  自動更新されます。**ここを止めると、数か月後に HTTPS が使えなくなります**

Tailscale は `--no-logs-no-support` を付けて起動すると、ログを送らなくなります。Tailscale は接続先の
最新の一覧を公開しているので、使っているバージョンと照らし合わせてください。

## 閉じたサーバーの更新

バージョンを固定していれば、変えるまで何も変わりません。

- **イメージを持ち込む**: インターネットにつながる機械で
  `docker pull ghcr.io/ikasast/voxinq-meeting/web:v4.0.1`（と `stt:v4.0.1`、または `stt:v4.0.1-cpu`）、
  続けて `docker save -o voxinq-4.0.1.tar <イメージ>`。サーバーで `docker load -i voxinq-4.0.1.tar`、
  `VOXINQ_VERSION=v4.0.1` にして `docker compose up -d`
- **または、更新の間だけ `ghcr.io` への出口を開け**、終わったら閉じます
- **先にバックアップを取ってください**（*設定 → データ*）。4.x の中のマイグレーションは追加だけなので、
  戻すには前のバージョンに固定し直すだけです
- リリースが新しいモデルを必要とする場合（まれ）は、最初と同じ方法で取得します

## Android アプリ

- **更新**は GitHub からスマホへ来ます。GitHub に届かないスマホには APK を渡して手で入れてください。
  サーバーのアドレスと未送信のものは保たれます
- **自前の認証局**（構成 2 と 3）: リリース版は Android に最初から入っている認証局だけを信頼し、
  スマホに後から追加した認証局は信頼しません。自前の CA を使うには、それを信頼するアプリのビルドが
  必要で、公開しているアプリは今のところ対応していません
- サーバーに届かないときはスマホで録音し、後で送ります。閉じたサーバーかどうかに関わらず同じです

## 入ってよいものを固める

閉じても、本来あるべき入口は残ります。固めるのはそこです。

- **Tailscale のアカウント**: ログインできる人は tailnet に端末を追加できます
  - **二段階認証**を必須にしたログイン方法（Google、Microsoft、GitHub、Okta など）を使う
  - **端末の承認**をオンにし、新しい端末は管理者の承認を待つようにする
  - **Tailnet Lock** を検討する。新しい端末は既に信頼している端末の署名が必要になり、アカウントが
    乗っ取られても端末を追加できません
  - **アクセス規則**（ACL）で、Voxinq が必要な人だけがサーバーの該当ポートにだけ届くようにする。
    サーバーにはタグを付ける
- **Voxinq のアカウント**: パスワードの共有ではなくアカウントを作ってください
  （[セキュリティと外部公開](security.md#複数人で使うアカウント)）。発言と議事録はアカウントごとの鍵で
  暗号化されます
  - tailnet の内側では Tailscale の ID で本人と分かり、パスワードは聞かれません。ID は鍵を持たない
    ので、鍵が閉じていればパスワードを 1 回聞きます。ただし**鍵が開いている間**（誰かが使っている、
    またはキューに仕事がある間）は ID だけで読めます。**Tailscale のアカウントが最も重要なのは
    このためです**
  - `VOXINQ_SIGNUP=closed` にして、初めて見る tailnet の ID が勝手にアカウントにならないようにし、
    `VOXINQ_KEY_SECRET` を設定してください（[設定](setup.md#ファイルで設定するものenv)）
- **端末**: なくしたスマホやノート PC が、残る入口です
  - 画面ロックを必須にする
  - **アプリのロックを必須にする**（*管理 → セキュリティ → アプリのロックを必須にする*）。各スマホの
    アプリは開くときに指紋・顔・画面ロックでの確認を求め、画面ロックの無いスマホは設定するまで中身を
    表示しません。録音の開始は止めません。守るのはアプリ側で、サーバーからは確かめられません
  - なくした端末はすぐに tailnet から外す。それでサーバーに届かなくなります
  - 全端末からログアウトする（*アカウント → すべての端末からログアウト*）。管理者は *管理 → メンバー* で
    アカウントを無効化することもでき、その場でセッションが終わります
  - Android アプリは未送信の録音をアプリ専用の領域に置き、Android が端末ごと暗号化しています
